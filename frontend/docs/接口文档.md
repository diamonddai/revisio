# 接口说明

> 每个请求包含 1. 用户交互流程 2. 接口基本信息 3. 请求参数 4. 响应数据。Base URL 为 `VITE_API_BASE` 或默认 `/api`。

---

## 零、完整数据结构（与模拟数据集一致）

本项目**仅支持「完整案例」**作为用户上传的数据结构，即与模拟数据集同构的 **chart_spec.json（Vega-Lite）+ metadata.json** 形式。**前端 UI 形式保持不变**；用户上传的数据**必须**为上述完整数据结构。后端与 Agent 据此理解并修改 Vega-Lite 代码与 metadata，生成新变体（如 chart_spec_v1.json），再渲染为变体图供前端展示。

**完整案例**单条目录结构（与 `data_README.md` / 模拟数据集一致）：

```
某案例/
├── data.csv           # 原始数据（可选，部分图表已嵌入 spec 则可不传）
├── chart_spec.json    # Vega-Lite 规范，数据可嵌入；Agent 主要修改此文件生成 chart_spec_v1.json 等
├── metadata.json      # 图表元信息（标题、描述、主题等），供 Agent 与后端使用
├── visualization.svg # 可选，由 chart_spec 渲染得到的预览图
└── visualization.html # 可选，独立预览页
```

- **chart_spec.json**：后端与 Agent 会解析并可能修改（如改数据范围、标注、标题），生成新版本如 `chart_spec_v1.json`，再渲染得到该节点的变体图（对应传播树节点 `imageUrl`）。
- **metadata.json**：可含图表描述、主题等，与前端「对图表的理解」「主题」可一致或由后端补充，供 Agent 决策。

下文约定**上传完整案例**接口与**开始模拟**的入参与传播树节点出参（含可选 `chartSpecUrl` / `chartSpec`）。

## 一、上传完整案例（结构化输入，与模拟数据集一致）

用户通过本接口上传与模拟数据集同构的「完整案例」（chart_spec + metadata）后，方可发起模拟。由用户在界面上选择本地 **chart_spec.json**、**metadata.json** 等文件上传。

### 1. 用户交互流程

1. 用户在「上传原始可视化」区域点击后，**选择本地一个包含完整数据结构的文件夹**（如 `01_global_temperature`），该文件夹内须包含 **chart_spec.json**（必填）、**metadata.json**（必填），以及可选 **data.csv**、可选预览图（如 **visualization.svg**）；若缺少必填文件则前端提示并拒绝上传。
2. 前端将上述文件以 FormData 形式 **POST 到 `/api/upload-case`**。
3. 后端：存储并返回 **caseRef**（或分别返回 chartSpecRef、metadataRef、dataRef、imageRef），供「开始模拟」时使用。
4. 前端在「开始模拟」时传 **caseRef**，后端与 Agent 读取 chart_spec.json、metadata.json，生成 chart_spec_v1.json 等变体并渲染为节点变体图。

### 1.1 接口基本信息

- **请求路径**：`/api/upload-case`
- **请求方式**：POST
- **接口描述**：上传与模拟数据集结构一致的完整案例（Vega-Lite + 元数据），供后端与 Agent 使用并生成变体；当前为模拟输入的**唯一**上传方式。

### 1.2 请求参数

- **参数格式**：FormData（multipart）
- **字段说明**：

| 字段名     | 类型 | 必填 | 说明 |
|------------|------|------|------|
| chart_spec | File | 是   | Vega-Lite 规范文件（JSON），Agent 会解析并可能修改生成 chart_spec_v*.json |
| metadata   | File | 是   | 图表元信息（JSON），如描述、主题等 |
| data       | File | 否   | 原始数据文件（如 data.csv），若图表数据已嵌入 chart_spec 可不上传 |
| image      | File | 否   | 预览图（SVG/PNG 等），用于前端预览与根节点展示；不传则后端可由 chart_spec 渲染 |

### 1.3 响应数据

- **参数格式**：JSON
- **字段说明**：返回案例引用，供「开始模拟」请求使用。

| 字段名       | 类型   | 说明 |
|--------------|--------|------|
| caseRef     | string | 可选，统一案例引用 ID，后端可根据此 ID 取到 chart_spec、metadata 等 |
| chartSpecRef | string | 可选，chart_spec 的 URL 或后端存储标识 |
| metadataRef  | string | 可选，metadata 的 URL 或后端存储标识 |
| dataRef     | string | 可选，data 的 URL 或标识 |
| imageRef    | string | 可选，预览图 URL 或 dataUrl，可用于前端预览与 imageRef 入参 |

- **响应样例**：

```json
{
  "caseRef": "case-abc123",
  "chartSpecRef": "https://example.com/store/abc/chart_spec.json",
  "metadataRef": "https://example.com/store/abc/metadata.json",
  "imageRef": "https://example.com/store/abc/visualization.svg"
}
```

前端在「开始模拟」时传 **caseRef**；不再使用 imageRef 作为模拟输入。

## 二、根据用户配置发起「开始模拟」请求

### 2. 用户交互流程

1. 用户已在左侧完成：**上传完整案例**（调用 `/api/upload-case` 获得 caseRef）、**手动输入「对图表的理解」**（可预填自 metadata）、**选择环境参数**（最大深度、Agent 数量）、**为每个 Agent 设置 Profile**（仅 **角色 role** 与 **平台 institution**，无 motivation；选项来自 codebook），未设置的卡片为灰色、设置后按角色颜色点亮。
2. 用户点击「开始模拟」。
3. 前端：将 `agentCount`、`agentCategories`、`description`、**caseRef**、**maxDepth**（用户选择的最大深度）、**agentProfiles**（每个 Agent 的 `{ role, institution }`，与 agentCount 一一对应）**以 JSON POST 到 `/api/simulation/start`**。若用户未上传案例（无 caseRef），前端可降级为本地演示数据，不请求本接口。
4. 后端：  
   - **方式 A（同步）**：执行模拟后直接返回传播树、Agent Log、摘要、路径偏移趋势等，前端收到后写入全局状态，中间栏展示传播树与 AGENT LOG，右侧展示偏移分析。  
   - **方式 B（异步）**：返回 `{ ok: true, taskId: "xxx" }`，前端再通过轮询或 WebSocket 按 taskId 拉取结果；结果结构同方式 A 中返回的数据。
5. 前端：收到结果后设置 `tree`、`agentLog`、`summary`、`pathOffsetTrend`、`overallVariantDescription`、`variantImageUrl` 等。**中间面板（传播模拟）与后端衔接方式**：**仅依赖本接口一次返回的 `tree` + `agentLog`**，无需再请求其他接口。传播树根据 `tree.nodes`、`tree.edges` 渲染；每个节点框内展示该节点的变体图（根节点 SRC 用用户上传图，其余节点用该节点的 `imageUrl`）；节点上方小圆点颜色与「节点类型」图例一致（由 `nodeType` 映射）。**边的线型**由目标节点的 `operations` 推断：DATA 层→长虚线、TEXT 层→实线、VISUAL 层→短虚线（见 codebook 三、框架操作分层）；若一条边对应多层级则前端会绘制多条线型。AGENT LOG 直接由 `agentLog[]` 按时间顺序展示。用户**点击节点/节点下图**后，**右侧偏移分析栏**展示：**预览**（当前变体图）、**过程**（从根到该节点按 Agent 分组的修改过程，按 DATA/VISUAL/TEXT 三层面展示）、**偏移趋势**；仅展示节点的 **role**、**institution**（若有），不展示 motivation。未选节点时右侧展示整体偏移分析。
6. 界面：中间为传播树（曲线连线按 DATA/TEXT/VISUAL 区分线型、左上角节点类型图例）+ AGENT LOG；右侧为预览、过程流（Agent→操作按三层面）、偏移趋势图。

### 2.1 接口基本信息

- **请求路径**：`/api/simulation/start`
- **请求方式**：POST
- **接口描述**：根据用户上传的图表（caseRef）、对图表的理解、Agent 数量与类别等配置，启动传播模拟。**中间面板的传播树与 AGENT LOG 完全由本接口的响应驱动**：同步时在同一次响应中返回 `tree`、`agentLog` 等；异步时先返回 `taskId`，前端再按 taskId 拉取到相同结构的结果后，同样写入 `tree`、`agentLog`，中间面板据此渲染，无需为传播结构或节点列表单独请求其他接口。

### 2.2 请求参数

- **参数格式**：JSON（Content-Type: application/json）
- **字段说明**：

| 字段名          | 类型     | 必填 | 说明 |
|-----------------|----------|------|------|
| agentCount      | number   | 是   | 智能体数量，前端范围 0–6 |
| agentCategories | string[] | 是   | Agent 类别列表，与 agentCount 一致；前端由 agentProfiles 的 role 推导，与 **codebook 一** 一致，共四种。取值：`"Bridger"` \| `"Extender"` \| `"Adverser"` \| `"Amplifier"` |
| agentProfiles   | object[] | 否   | 每个 Agent 的 profile，与 agentCount 一一对应；每项 `{ role: string, institution: string }`。**role** 取值见 codebook 一（Bridger / Extender / Adverser / Amplifier），**institution** 取值见 codebook 二（如「政府/官方机构/国际组织」「社交媒体」等）；前端用下拉菜单从 codebook 选择，仅保留 role+institution，**不再传 motivation**。 |
| maxDepth        | number   | 否   | 用户选择的最大深度（传播树深度），前端必传 |
| description     | string   | 否   | 用户手动填写的「对图表的理解」 |
| imageRef        | string   | 否   | 已废弃，不作为模拟输入 |
| caseRef         | string   | 否   | 上传完整案例（/api/upload-case）后返回的案例 ID，后端据此读取 chart_spec、metadata，供 Agent 生成变体；**当前为模拟唯一输入，前端必传** |
| chartSpecRef    | string   | 否   | 若未用 caseRef，可单独传 chart_spec 的 URL 或存储标识 |
| metadataRef     | string   | 否   | 若未用 caseRef，可单独传 metadata 的 URL 或存储标识 |

- **请求样例**：

```ts
const res = await fetch("/api/simulation/start", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    agentCount: 4,
    agentCategories: ["Bridger", "Adverser", "Extender", "Amplifier"],  // 与 agentCount 一致，由 agentProfiles 的 role 推导
    agentProfiles: [
      { role: "Bridger", institution: "NOAA官方机构" },
      { role: "Adverser", institution: "社交媒体" },
      { role: "Extender", institution: "学术机构" },
      { role: "Amplifier", institution: "新闻媒体" },
    ],
    maxDepth: 3,
    description: "NOAA全球年均温度偏差柱状图，x轴1880-2023，y轴温度偏差1.5度",
    caseRef: "case-abc123",  // 来自 POST /api/upload-case 的 caseRef
  }),
});
const data = await res.json();
```

### 2.3 响应数据

- **参数格式**：JSON

后端可采用两种方式之一（或同时支持）：

**方式 A：仅返回是否接受 + 可选 taskId（异步）**

| 字段名  | 类型    | 说明 |
|---------|---------|------|
| ok      | boolean | 是否成功接受任务 |
| taskId  | string  | 可选，异步任务 ID，用于轮询或 WebSocket 拉取结果 |

- **响应样例（异步）**：

```json
{
  "ok": true,
  "taskId": "sim-abc123"
}
```

**方式 B：同步返回完整模拟结果**

除 `ok` 外，直接返回前端会写入状态的数据结构（下表为前端会使用的字段）：

| 字段名   | 类型   | 说明 |
|----------|--------|------|
| ok       | boolean | 是否成功 |
| taskId   | string   | 可选，若同步则可不返 |
| tree     | object   | 传播树，结构见下「传播树」 |
| agentLog | array    | Agent 日志列表，每项见下「单条 Agent 日志」 |
| summary  | object   | 模拟结果摘要，见下「模拟结果摘要」 |
| pathOffsetTrend | array | 路径偏移趋势点列表，见下「路径偏移趋势点」 |
| overallVariantDescription | string | 整体变体描述文案 |
| variantImageUrl | string | 可选，最终变体图 URL 或 base64 |

**传播树 tree**（中间面板传播图与节点框内变体图的数据来源）：

- **nodes**：每个节点建议带上 **imageUrl**（该节点对应「传播后产生的变体图」的 URL 或 base64）。输入为完整案例（caseRef）时，后端/Agent 基于 chart_spec.json、metadata.json 生成变体 Vega-Lite（如 chart_spec_v1.json），并渲染得到该节点的变体图，填入 **imageUrl**；前端在**中间面板节点框内**直接使用 `imageUrl` 展示，并在用户点击该节点时在**右侧偏移分析栏**放大展示同一 `imageUrl`。可选同时返回该变体的 **chartSpecUrl** 或 **chartSpec**（见下），供前端展示或下载。根节点 SRC 可由前端用上传案例返回的 imageRef（或由 chart_spec 渲染得到的预览图）展示，后端可不返 SRC 的 imageUrl。**nodeType** 用于前端绘制节点上方小圆点颜色，与「节点类型」图例一致（与 codebook 四角色对应：Bridger、Extender、Adverser、Amplifier）。前端**右侧偏移分析**仅展示节点的 **role** 与 **institution**（若有），**不再展示 motivation**；若后端仍返回 motivation，前端可忽略或仅作备用。
- 其余字段结构如下：

```ts
{
  nodes: Array<{
    id: string;
    label: string;
    actionLabel?: string;
    nodeType: "neutral" | "authority" | "amplifier" | "analyst" | "bridger" | "adverser" | "anxiety" | "mobilizer";
    platform?: "longform" | "shortform" | "video" | "community";  // 前端 UI 不展示，后端可选
    role?: string;              // 有则右侧展示「角色」
    motivation?: string;         // 有则右侧展示「动机」
    offset?: "none" | "minor" | "sig" | "major";
    imageUrl?: string;   // 该节点变体图（由 chart_spec_v* 渲染或直接生成），用于树节点框内展示与右侧放大展示
    chartSpecUrl?: string;  // 可选，该节点变体对应的 Vega-Lite 规范 URL（如 chart_spec_v1.json），后端生成变体时可返回
    chartSpec?: object;    // 可选，该节点变体 Vega-Lite 规范内联（与 chartSpecUrl 二选一即可）
    operations?: string[];
    variantDescription?: string;
    layers?: string;
  }>;
  // 以上带 ? 的字段均为可选：有则返回、前端在右侧偏移分析栏对应展示；无则不返、前端不显示该块。
  edges: Array<{ id: string; source: string; target: string; offset?: string }>;
  nodeCount: number;
  edgeCount: number;
  maxDepth: number;
  highestOffsetPath: string;
  topologyType: string;
}
```

**三个层面的操作（DATA / VISUAL / TEXT）如何得到**：

- **数据来源**：由后端在「开始模拟」响应里、对每个节点通过 **`tree.nodes[].operations`**（`string[]`）返回。
- **格式约定**：每条字符串以层级前缀开头，后面跟具体操作描述；前端根据**前缀**解析出属于哪一层：
  - 以 **`"DATA"`**（或 `"DATA "`）开头 → 数据层面（见 `docs/codebook.md` 三、数据层面）
  - 以 **`"TEXT"`** 开头 → 文本层面（见 codebook 三、文本层面）
  - 以 **`"VISUAL"`** 开头 → 视觉层面（见 codebook 三、视觉层面）
- **示例**：`["DATA select data range", "TEXT delete source", "VISUAL change chart color"]` → 前端解析为 DATA 一条、TEXT 一条、VISUAL 一条。
- **前端用途**：  
  1）**中间面板边的线型**：由**目标节点**的 `operations` 推断——存在 DATA→长虚线、TEXT→实线、VISUAL→短虚线；多层级则画多条线型。  
  2）**右侧「过程」**：从根到当前节点路径上，按 Agent 分组，每个 Agent 下按 DATA / TEXT / Visual 三块展示对应操作；语义与 codebook 三、框架操作一致。

后端只需保证每个节点的 `operations` 中每条字符串**以 DATA、TEXT 或 VISUAL 开头**（大小写不限，前端按前缀解析），即可与前端三层面展示和边线型一致。

**单条 Agent 日志 agentLog[]**：

```ts
{ id: string; time: string; source: string; message: string; offsetLevel?: "none" | "minor" | "sig" | "major" }
```

**模拟结果摘要 summary**：

```ts
{ agentCount: number; edgeCount: number; highestOffset: "none" | "minor" | "sig" | "major" }
```

**路径偏移趋势点 pathOffsetTrend[]**：

```ts
{ step: string; offset: "none" | "minor" | "sig" | "major" }
```

- **响应样例（同步，仅示意关键字段）**：节点中的 `imageUrl` 为可选，但建议每个非根节点返回，以便前端在树中及右侧放大展示变体图。

```json
{
  "ok": true,
  "tree": {
    "nodes": [
      { "id": "SRC", "label": "NOAA 全球温度偏差柱状图", "actionLabel": "源", "nodeType": "neutral", "offset": "none" },
      { "id": "V2", "label": "@ClimateTruth", "nodeType": "amplifier", "role": "influencer", "motivation": "对抗", "offset": "major", "imageUrl": "data:image/png;base64,...", "operations": ["DATA select data range", "TEXT delete source"], "variantDescription": "截取1998-2012年数据范围...", "layers": "D+T major" }
    ],
    "edges": [
      { "id": "e1", "source": "SRC", "target": "V1" },
      { "id": "e2", "source": "SRC", "target": "V2", "offset": "major" }
    ],
    "nodeCount": 6,
    "edgeCount": 5,
    "maxDepth": 2,
    "highestOffsetPath": "SRC->V2 (major)",
    "topologyType": "tree"
  },
  "agentLog": [
    { "id": "log-1", "time": "00:00:00", "source": "SYSTEM", "message": "初始化模拟环境..." },
    { "id": "log-2", "time": "00:00:12", "source": "CLIMATE_TRUTH", "message": "Agent #2 截取数据范围...", "offsetLevel": "major" }
  ],
  "summary": { "agentCount": 5, "edgeCount": 5, "highestOffset": "major" },
  "pathOffsetTrend": [
    { "step": "SRC", "offset": "none" },
    { "step": "V2", "offset": "major" }
  ],
  "overallVariantDescription": "截取1998-2012年数据范围(温度停滞期)，删除NOAA来源标注..."
}
```

若采用异步（方式 A），则需另行约定「根据 taskId 获取上述结果」的接口（如 GET `/api/simulation/result?taskId=xxx` 或 WebSocket 消息格式），返回结构同上。


### 2.4 中间面板与后端衔接（服务于研究问题）

| 研究关注点 | 中间面板呈现 | 后端需在「开始模拟」响应中提供 |
|-----------|--------------|------------------------------|
| 传播结构（谁传谁） | 传播树拓扑（节点 + 有向边） | `tree.nodes`、`tree.edges`，结构一致 |
| 每个环节的可视化变体 | 节点框内的变体图 | `nodes[].imageUrl`（或可解析的 ref） |
| 节点角色类型 | 节点上方小圆点 + 图例 | `nodes[].nodeType`（与 codebook 四角色 Bridger/Extender/Adverser/Amplifier 对应） |
| 操作与偏移详情 | 点击节点后右侧展示 | `nodes[].operations`、`variantDescription`、`offset` 等 |
| 过程的时间顺序 | AGENT LOG | `agentLog[]` 按时间排序 |

**结论**：中间面板**不单独请求任何接口**，仅根据本接口一次返回的 `tree` + `agentLog` 渲染传播树与日志；后端保证该响应结构完整即可与前端对齐。

- **请求路径**：`/api/health`

### 3.2 请求参数

### 3.3 响应数据

- **参数格式**：JSON

| 字段名 | 类型    | 说明       |
|--------|---------|------------|
| ok     | boolean | 是否正常   |

## 四、汇总

| 用户在干什么             | 发出的请求                         | 说明 |
|--------------------------|------------------------------------|------|
| 上传原始可视化图片       | POST `/api/upload` (FormData)      | 已废弃，不作为模拟输入 |
| 上传完整案例（Vega-Lite+元数据） | POST `/api/upload-case` (FormData) | 与模拟数据集一致，传 chart_spec、metadata 等；返回 caseRef 等，供开始模拟时使用；**当前为模拟唯一上传方式** |
| 点击「开始模拟」         | POST `/api/simulation/start` (JSON) | 必接：携带 agentCount、agentCategories、description、caseRef；后端同步或异步返回模拟结果；节点可带 chartSpecUrl/chartSpec |
| 启动/运维探测后端可用性  | GET `/api/health`                  | 可选：前端未在 UI 中调用 |
