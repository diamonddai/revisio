# 前端项目整体解析

本文档从入口到三栏功能，按「从头到尾」顺序梳理整个前端项目结构、数据流与联调关系。

---

## 一、技术栈与入口

| 项目 | 说明 |
|------|------|
| **构建** | Vite 7 + React 19 |
| **语言** | TypeScript |
| **UI** | Ant Design 5、部分自定义 inline style |
| **图表** | Recharts（偏移趋势折线图）、@xyflow/react（传播树） |
| **请求** | Axios（baseURL 来自 `VITE_API_BASE`，默认 `/api`） |

**入口链路：**

```
index.html
  → <div id="root"/> + <script src="/src/main.tsx"/>
main.tsx
  → StrictMode + App
App.tsx
  → ErrorBoundary + ConfigProvider(antd) + AppLayout
AppLayout.tsx
  → SimulationProvider + 三栏网格布局 → SetupPanel | PropagationPanel | OffsetPanel
```

- **index.html**：挂载根节点、引入 Inria Sans 字体、标题「传播模拟与偏移分析」。
- **main.tsx**：React 根渲染、全局样式 `index.css`。
- **App.tsx**：全局错误边界、Ant Design 主题（如 `borderRadius: 8`）、实际内容交给 `AppLayout`。

---

## 二、整体布局（AppLayout）

- **底板**：整页 `#EDEFF2`，`height: 100vh`，三栏栅格。
- **三栏标题**：同一行三个标题条（#808993 底、白字）——「设置模拟」「传播模拟」「偏移分析」。
- **三栏内容**：
  - **列宽**：`minmax(360px, 1fr) | minmax(420px, 2.2fr) | minmax(360px, 1fr)`，左中右等分。
  - **左栏**：白底、圆角，内容区用 `scale(0.88)` 缩小以便一屏多 Agent；内嵌 **SetupPanel**。
  - **中栏**：白底、圆角，内嵌 **PropagationPanel**。
  - **右栏**：白底、圆角，`overflowX: visible`、`overflowY: hidden`，内嵌 **OffsetPanel**。

所有「模拟相关」状态与 setter 都来自 **SimulationProvider**，三栏通过 `useSimulation()` 读写同一份全局状态。

---

## 三、全局状态（context/simulation.tsx）

**SimulationProvider** 提供整应用唯一的模拟上下文，主要状态可归类为：

| 分类 | 状态 | 用途 |
|------|------|------|
| **上传与设置** | `preview`, `caseRef`, `agentCount`, `maxDepth`, `agentProfiles`, `description` 等 | 左侧上传结果、环境参数、用户理解、Agent 配置 |
| **模拟结果** | `status`, `summary`, `tree`, `agentLog` | 模拟是否完成、树与日志 |
| **选中与偏移** | `selectedNode`, `pathOffsetTrend`, `variantImageUrl`, `overallVariantDescription` 等 | 右侧预览、过程流、偏移趋势图 |

- **agentProfiles**：每项为 `{ role, institution }`，与 `docs/codebook.md` 一致，无 `motivation`。
- **agentCategories**：由前端从 `agentProfiles` 的 `role` 推导，用于请求体 `agentCategories`，与后端约定一致。

数据流：**左侧写入**（上传、参数、开始模拟）→ **Context 更新** → **中/右栏读取**（树、选中节点、pathOffsetTrend 等）。

---

## 四、API 层（lib/api.ts）

| 接口 | 方法 | 作用 |
|------|------|------|
| **POST /upload-case** | FormData(chart_spec, metadata, 可选 data/image) | 上传案例，返回 `caseRef`，供「开始模拟」使用 |
| **POST /simulation/start** | JSON body | 开始模拟，必传 `caseRef`；可选 `maxDepth`、`agentCount`、`agentProfiles`、`description` 等 |
| **GET /health** | - | 健康检查 |

- **startSimulation** 请求体包含：`agentCount`、`agentCategories`（由 agentProfiles 推导）、`agentProfiles`（仅 role + institution）、`maxDepth`、`description`、`caseRef`。
- 超时或后端不可用时，前端会走 **applyMockTree** 等演示数据并 `setTree`/`setPathOffsetTrend` 等，保证界面可演示。

---

## 五、左侧：设置模拟（SetupPanel）

**职责：** 上传案例、填写理解与参数、配置 Agent 池、发起「开始模拟」。

1. **上传文件**
   - 用户选择文件夹，需包含 `chart_spec.json`、`metadata.json`，可选 `data.csv`、图片等。
   - 调用 `uploadCase`，得到 `caseRef`；同时用 FileReader 生成预览图 `dataUrl` 写入 `preview`，便于预览框内**整体缩放**显示（预览框固定高度、`objectFit: contain`、外层 `overflow: hidden`）。
   - 上传成功后清空与本次案例相关的状态（如 `tree`、`selectedNode`、`pathOffsetTrend`）。

2. **预览**
   - 使用 `preview?.dataUrl` 在固定高度预览框内展示，缩放后完整显示、不裁切。

3. **对图表的理解**
   - `Input.TextArea` 绑定 `description`，占位示例为 NOAA 图表说明。

4. **环境参数**
   - `maxDepth`、`agentCount` 用 Slider 调节；`agentCount` 变化时通过 `useEffect` 同步 `agentProfiles` 长度（不足补 `{ role: null, institution: null }`，超出截断）。

5. **Agent 池（Agent Profile）**
   - 展示 `agentCount` 个卡片；未配置时为灰底（GREY_BG），配置 role/institution 后按角色上色（ROLE_COLORS）。
   - 点击编辑：大 robot 图标 + 四角色横排按钮（Bridger/Extender/Adverser/Amplifier）+ 平台下拉（INSTITUTIONS）+「完成」。
   - 角色选项占满一行、略放大；底色与 profile 框一致（GREY_BG），非白底。

6. **开始模拟**
   - 点击后根据 `caseRef`、`agentCount`、`agentProfiles`（及推导的 `agentCategories`）、`maxDepth`、`description`、`topic` 调用 `startSimulation`。
   - 成功则把返回的 `tree`、`agentLog`、`summary`、`pathOffsetTrend`、`overallVariantDescription`、`variantImageUrl` 写入 Context。
   - 失败或超时则使用本地 mock 数据并同样写入 Context。

---

## 六、中间：传播模拟（PropagationPanel）

**职责：** 展示传播树，节点可点击并驱动右侧偏移分析。

- 使用 **@xyflow/react**：自定义节点类型 `variantImage`（上方彩色圆 + robot 图标，下方白框内变体图或空）。
- 节点颜色由 `nodeType`/`role` 等映射（NODE_TYPE_COLOR、AGENT_PROFILE_COLORS）。
- 边样式按操作层级（DATA/TEXT/VISUAL）区分：DATA 疏虚线、TEXT 实线、VISUAL 密虚线等（EDGE_STYLE_BY_LAYER）。
- 数据来源：`tree`（Context），即 `startSimulation` 返回或 mock 的 `PropagationTree`。
- 点击节点：`setSelectedNode(node)`，右侧据此展示该节点的预览、过程流与偏移趋势。

---

## 七、右侧：偏移分析（OffsetPanel）

**职责：** 展示当前节点的变体预览、从根到该节点的过程流、以及「上一节点 → 当前节点」的偏移趋势图。

1. **预览**
   - 有选中节点时：优先用 `selectedNode.imageUrl`，否则 `variantImageUrl`；无图时占位文案。
   - 与左侧预览框风格一致（如底色），整图缩放、不超出框。

2. **过程**
   - 标题「过程」在框外，与「预览」「偏移趋势」对齐。
   - 从根到 `selectedNode` 的路径 `pathToSelected` 用 **ProcessTimeline** 展示：左侧彩色 robot 图标（与 Agent 池颜色一致）、角色名（Publisher / Bridger 等）、虚线串联；非 Publisher 节点可展开/收起 DATA/TEXT/Visual 操作块；Publisher 不展示操作块。
   - 过程框可滚动，高度可配置（processBoxMinHeight/MaxHeight），与偏移趋势区间用固定 padding/占位控制间距，保证「偏移趋势」位置固定、三种状态（未模拟/已模拟未选节点/已选节点）布局一致。

3. **偏移趋势**
   - Recharts 折线图：**仅两点**——「上一节点」与「当前节点」，直线连接；纵轴为偏移等级（none/minor/sig/major），横轴为两节点 id（如 SRC、V2）。
   - 数据来自 `pathOffsetTrend` + `pathToSelected`，只取路径上最后两个节点对应数据；无选中或无数据时显示占位文案。
   - 图表区无外框，仅标题+图；与过程框的间距通过 `offsetTrendBlockPaddingTop` 等控制，避免与过程框重叠。

## 八、类型与常量

- **types/contracts.ts**：与后端/接口对齐的类型定义（TopicType、PlatformKey、AgentCategory、AgentNode、PropagationTree、PathOffsetPoint、OffsetLevel、UploadPreview、SimulationStatus 等）。
- **constants/codebook.ts**：ROLES（Bridger/Extender/Adverser/Amplifier）、INSTITUTIONS、FRAME_LAYERS（DATA/TEXT/VISUAL）、AgentProfileEntry；与 `docs/codebook.md` 一致。
- **constants/agentProfile.ts**：角色与颜色映射（ROLE_COLORS、AGENT_PROFILE_COLORS），供左侧 Agent 池与右侧过程流、中间传播树节点着色。
- **features/setup/panel1Styles.ts**：左侧面板的字体、颜色、尺寸等（如 previewMinHeight、uploadRadius、agentCardBg）。

## 九、数据流小结

```
用户上传文件夹
  → uploadCase() → caseRef + preview.dataUrl
  → 用户填写描述、调节 maxDepth/agentCount、配置 agentProfiles
  → 点击「开始模拟」
  → startSimulation({ caseRef, agentProfiles, agentCategories, maxDepth, description })
  → 后端返回 tree, agentLog, summary, pathOffsetTrend, variantImageUrl, ...
  → Context 更新 → 中间栏展示 tree，右侧可展示默认 variantImageUrl

用户点击传播树某节点
  → setSelectedNode(node)
  → 右侧：预览用 node.imageUrl｜variantImageUrl；过程用 pathToSelected；偏移趋势用 pathOffsetTrend 中上一节点与当前节点两点
```

- **左侧**：唯一写入口（上传、参数、Agent 配置、发起模拟）。
- **中间**：只读 `tree` 与节点点击，写 `selectedNode`。
- **右侧**：只读 `tree`、`selectedNode`、`pathOffsetTrend`、`variantImageUrl` 等，无写操作。

整体与 `docs/接口文档.md`、`docs/后端方案.md` 对齐：上传与开始模拟的请求体、字段含义、枚举与 codebook 一致；前端不传 `motivation`，仅传 role + institution。
